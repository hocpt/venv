{{ title or "Tài liệu API cho Client" }}

Trang này mô tả chi tiết các API endpoints mà Client (Điện thoại / MacroDroid) cần sử dụng để tương tác với Server.

Vui lòng đảm bảo Client gửi đúng Method, URL, Headers và cấu trúc Request Body/Payload như mô tả.

{# ======================================================= #} {# === API 1: Lấy Nhiệm vụ / Chiến lược (/phone/get_strategy) === #} {# ======================================================= #}

1. Lấy Nhiệm vụ / Chiến lược

Client gọi API này để kiểm tra và nhận nhiệm vụ mới (nếu có) được giao cho cặp Device/Account đang hoạt động. Server sẽ trả về gói JSON chứa toàn bộ chiến lược đã biên dịch.

Method: POST
URL Endpoint: /phone/get_strategy
Header yêu cầu: Content-Type: application/json

Request Body (JSON)

Client cần gửi một JSON object chứa các thông tin sau:

  • device_id (String*): ID duy nhất của thiết bị đang gọi API (phải khớp với ID trong bảng `devices`).
  • account_id (String*): ID của tài khoản ứng dụng mà client đang muốn chạy nhiệm vụ (phải khớp với ID trong bảng `accounts` và đã được liên kết với `device_id` trong `device_accounts`).
Ví dụ Request Body: 
{
  "device_id": "test_device_001",
  "account_id": "tiktok_test_1"
}

Success Response (HTTP 200 OK)

Có 2 trường hợp thành công:

Trường hợp 1: Có nhiệm vụ mới được giao

Server trả về một JSON object lớn chứa "Gói Chiến lược" (Strategy Package). Client cần parse gói này để thực thi. Cấu trúc chính bao gồm:

  • metadata: Chứa thông tin như `assignment_id` (ID nhiệm vụ này, **Client phải lưu lại để dùng khi report**), `strategy_id`, `strategy_name`, `strategy_version`...
  • execution_config: Chứa cấu hình thực thi như `initial_stage_id` (stage bắt đầu), `default_wait_ms`...
  • account_context: Chứa `target_data` (mục tiêu/tham số riêng cho nhiệm vụ này, ví dụ: `{"target_count": 100}`).
  • stages_recognition: Dictionary chứa các quy tắc để Client nhận diện các stages (`{"stage_id": {"rules": [...]}}`).
  • action_sequence: Mảng (list) chứa các bước (steps) cần thực thi. Mỗi step có thể là `simple`, `loop`, hoặc `conditional`.
Ví dụ Response (Có nhiệm vụ - Cấu trúc tham khảo): 
{
  "metadata": {
      "package_format_version": "1.2",
      "strategy_id": "tiktok_basic_swipe_like",
      "strategy_name": "TikTok Cơ bản: Lướt và Like",
      "strategy_version": "...",
      "compiled_at": "...",
      "assignment_id": 2   // <<< Client cần lưu ID này
  },
  "execution_config": {
      "initial_stage_id": "start",
      "max_run_time_minutes": 120,
      "default_wait_ms": {"min": 800, "max": 1500},
      "error_handling": "report_and_stop"
  },
  "account_context": {
      "target_data": {"c": "c"} // Ví dụ target data
  },
  "stages_recognition": {
       "start": {"description": "...", "rules": []},
       "tiktok_opened": {"description": "...", "rules": [...]},
       "feed_viewed": {"description": "...", "rules": [...]},
       // ... các stages khác ...
  },
  "action_sequence": [
      { // Bước 1: Simple
          "step_id": 6,
          "trigger": {"current_stage": "start", "user_intent": "start_flow"},
          "type": "simple",
          "macro_code": "APP_OPEN",
          "params": {"package_name": "com.zhiliaoapp.musically"},
          "next_stage_id": "tiktok_opened"
      },
      { // Bước 2: Simple
          "step_id": 7,
          "trigger": {"current_stage": "tiktok_opened", "user_intent": "wait_for_load"},
          "type": "simple",
          "macro_code": "SYS_WAIT",
          "params": {"duration_ms": 3000},
          "next_stage_id": "feed_viewed"
      },
      { // Bước 3: Loop
          "step_id": 8,
          "trigger": {"current_stage": "feed_viewed", "user_intent": "swipe_videos"},
          "type": "loop",
          "loop_config": { "type": "repeat_n", "count": 3 },
          "sequence": [{"macro_code": "UI_SWIPE_UP", "params": {}}],
          "next_stage_id": "videos_swiped"
      },
      // ... các steps khác ...
  ]
}
Trường hợp 2: Không có nhiệm vụ mới

Server trả về JSON đơn giản báo hiệu không có task.

Ví dụ Response (Không có nhiệm vụ): 
{
  "status": "no_task",
  "message": "No pending assignment found.",
  "retry_after_seconds": 300  // (Tùy chọn) Client nên chờ khoảng thời gian này (giây) trước khi hỏi lại
}

Error Response (HTTP 400, 404, 500)

Nếu có lỗi xảy ra (payload sai, không tìm thấy device/account/liên kết, lỗi server...), server sẽ trả về JSON với `status: "error"`.

Ví dụ Response (Lỗi): 
{
  "status": "error",
  "message": "Device or Account not registered/linked correctly."
}
{
  "status": "error",
  "message": "Failed to compile strategy package."
}
{
  "status": "error",
  "message": "Missing 'device_id' or 'account_id'."
}
{# ======================================================= #} {# === API 2: Báo cáo Trạng thái (/phone/report_status) === #} {# ======================================================= #}

2. Báo cáo Trạng thái / Log / UI State

Client gọi API này định kỳ hoặc khi có sự kiện quan trọng (hoàn thành step, gặp lỗi, kết thúc assignment) để gửi báo cáo về trạng thái, tiến độ, log chi tiết và trạng thái UI mới nhất lên Server.

Method: POST
URL Endpoint: /phone/report_status
Header yêu cầu: Content-Type: application/json

Request Body (JSON)

Client cần gửi một JSON object chứa các thông tin sau:

  • device_id (String*): ID của thiết bị.
  • account_id (String*): ID của tài khoản đang chạy.
  • assignment_id (Integer*): ID của nhiệm vụ đang báo cáo (**lấy từ metadata khi gọi /get_strategy**).
  • status_report (Object*): Chứa trạng thái tổng hợp của client.
    • current_status (String*): Trạng thái hiện tại ('running', 'completed', 'error', 'paused'...).
    • progress (Object?): Dữ liệu cập nhật tiến độ (ví dụ: `{"videos_watched": 1}`). Cấu trúc phụ thuộc vào `target_data` của assignment.
    • result (Object?): Dữ liệu kết quả cuối cùng khi trạng thái là 'completed' hoặc 'error'.
    • error_message (String?): Chi tiết lỗi nếu `current_status` là 'error'.
  • logs (Array?): **Danh sách** các log entry (dạng object) chi tiết về các hành động đã thực hiện kể từ lần báo cáo trước. Mỗi entry nên có ít nhất: `timestamp` (ISO 8601), `macro` (tên macro), `params` (object), `status` ('success'/'fail'/'skipped'/'error'), `error` (string/null), `stage` (stage lúc thực thi).
  • current_ui_state (Object?): **(Quan trọng cho App Map)** Trạng thái UI **thô** mới nhất client lấy được từ AutoInput UI Query. Object này chứa:
    • timestamp (String?): ISO 8601 timestamp lúc query UI.
    • package_name (String?): Tên package app.
    • activity_name (String?): Tên activity.
    • ids (Array?): Mảng các chuỗi resource ID (`["id1", "id2", null, ...]`).
    • texts (Array?): Mảng các chuỗi text (`["text1", null, "text3", ...]`).
    • coords (Array?): Mảng các chuỗi tọa độ `"x,y"` (`["1,2", "3,4", ...]`).
    • ...(Có thể thêm các mảng khác như `content_descs`, `clickables`...)
Ví dụ Request Body: 
{
  "assignment_id": 2,
  "device_id": "test_device_001",
  "account_id": "tiktok_test_1",
  "status_report": {
      "current_status": "running",
      "progress": {"videos_swiped_session": 3},
      "result": null,
      "error_message": null
  },
  "logs": [
      {"timestamp": "2025-04-23T11:05:01Z", "macro": "UI_SWIPE_UP", "params": {}, "status": "success", "error": null, "stage": "feed_viewed"},
      {"timestamp": "2025-04-23T11:05:03Z", "macro": "UI_SWIPE_UP", "params": {}, "status": "success", "error": null, "stage": "feed_viewed"},
      {"timestamp": "2025-04-23T11:05:05Z", "macro": "UI_SWIPE_UP", "params": {}, "status": "success", "error": null, "stage": "feed_viewed"}
  ],
  "current_ui_state": {
      "timestamp": "2025-04-23T11:05:06Z",
      "package_name": "com.zhiliaoapp.musically",
      "activity_name": ".MainActivity",
      "ids": ["com.zhiliaoapp.musically:id/desc", "com.zhiliaoapp.musically:id/like_icon", "..."],
      "texts": ["#hashtag", "Like", "..."],
      "coords": ["123,456", "789,123", "..."]
  }
}

Success Response (HTTP 200 OK)

Server xác nhận đã nhận và xử lý báo cáo. Có thể kèm theo yêu cầu hành động tiếp theo cho client.

Ví dụ Response: 
{
  "status": "success",
  "message": "Report received.",
  "action_required": null // hoặc "stop_assignment" nếu Admin đã hủy task này
}

Error Response (HTTP 4xx / 5xx)

Nếu payload không hợp lệ hoặc có lỗi server khi xử lý báo cáo.

Ví dụ Response (Lỗi): 
{
  "status": "error",
  "message": "Invalid report data: Missing 'assignment_id'."
}
{
  "status": "error",
  "message": "Internal server error processing report."
}
{# ======================================================= #} {# === API 3: Đăng ký / Cập nhật Thiết bị (/phone/register_device) === #} {# ======================================================= #}

3. Đăng ký / Cập nhật Thiết bị

Client gọi API này lần đầu hoặc định kỳ để đăng ký/cập nhật thông tin của chính nó (OS, model, version client) và danh sách các tài khoản nó đang quản lý (kèm trạng thái đăng nhập, clone context) với Server.

Method: POST
URL Endpoint: /phone/register_device
Header yêu cầu: Content-Type: application/json

Request Body (JSON)

  • device_id (String*): ID duy nhất của thiết bị.
  • device_info (Object?): Chứa thông tin thiết bị như `os`, `model`.
  • client_version (String?): Phiên bản MacroDroid hoặc script agent.
  • managed_accounts (Array*): Danh sách các tài khoản trên thiết bị. Mỗi phần tử là object:
    • account_id (String*)
    • platform (String*)
    • username (String?)
    • clone_context (String?): Ngữ cảnh clone ('main', 'dual', 'secure', 'user_xx'...). Để `null` hoặc bỏ qua nếu là app gốc.
    • status (String*): Trạng thái của tài khoản **trên thiết bị này** (ví dụ: 'active_logged_in', 'login_required', 'error', 'unknown'...).
Ví dụ Request Body: 
{
  "device_id": "test_device_001",
  "device_info": {
      "os": "Android 12",
      "model": "SM-G998B"
  },
  "client_version": "1.1",
  "managed_accounts": [
      {"account_id": "tiktok_test_1", "platform": "tiktok", "clone_context": null, "status": "active_logged_in"},
      {"account_id": "fb_user_clone", "platform": "facebook", "clone_context": "dual", "status": "login_required"}
  ]
}

Success Response (HTTP 200 OK)

{
  "status": "success",
  "message": "Device registered/updated."
}

Error Response (HTTP 400 / 500)

{
  "status": "error",
  "message": "Missing 'device_id'."
}
{
  "status": "error",
  "message": "Internal server error during registration."
}
