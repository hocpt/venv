README - Tổng hợp Tiến độ Dự án (Tính đến 21/04/2025)

I. Mục tiêu Tổng thể:

Xây dựng một hệ thống quản lý tự động hóa đa năng bao gồm:

AI Ngôn ngữ: Tự động tương tác dựa trên văn bản (bình luận, trả lời tin nhắn) sử dụng các chiến lược (Rules, Templates) hoặc gọi trực tiếp AI (Google Gemini). Phần này được xem là tương đối hoàn thiện về chức năng cơ bản, cần kiểm thử thực tế.
AI Điều khiển (Trọng tâm hiện tại): Tự động hóa các thao tác trên giao diện ứng dụng Android (TikTok, Facebook, Zalo...) thông qua Client MacroDroid được điều khiển bởi Server trung tâm.
Hệ thống Quản lý: Giao diện Admin Web (Flask) để định nghĩa chiến lược, quản lý tài khoản, thiết bị, giao việc và theo dõi kết quả. Hỗ trợ quản lý nhiều thiết bị, nhiều tài khoản/clone trên mỗi thiết bị.
II. Kiến trúc & Công nghệ:

Backend: Flask (Python), sử dụng Application Factory Pattern.
Database: PostgreSQL.
Server WSGI: Waitress (cho production).
Client Điều khiển: MacroDroid trên Android (kết hợp AutoInput plugin).
Giao tiếp: Server và Client giao tiếp qua REST API (sử dụng JSON).
AI: Google Gemini (thông qua ai_service.py).
III. Tình trạng Các Thành phần Chính:

A. Cơ sở dữ liệu:

Schema gốc (new_automation_schema.sql): Đã định nghĩa các bảng cho cấu hình AI Ngôn ngữ (accounts, rules, templates, template_variations, strategies (type='language'), strategy_stages, stage_transitions (type='language'), ai_personas, prompt_templates, api_keys) và các bảng hệ thống ban đầu (scheduler_commands, scheduled_jobs - vai trò giảm dần).
Schema Mở rộng (Cho AI Điều khiển & Quản lý):
Đã thêm các bảng:
devices: Lưu thông tin thiết bị vật lý (device_id PK, device_name, os_info, macrodroid_version, status, last_seen_at...).
device_accounts: Liên kết devices và accounts, lưu clone_context, app_package_name, status của liên kết. Có ràng buộc UNIQUE(device_id, account_id).
task_assignments: Bảng giao việc chính, liên kết device_account_id với strategy_id (loại 'control'), lưu status, priority, lịch chạy, target_data (JSONB - mục tiêu & tiến độ), result_data (JSONB - kết quả/lỗi).
Đã thêm bảng macro_definitions: Định nghĩa các macro con tái sử dụng (macro_code PK, description, app_target, params_schema JSONB). Đã có dữ liệu mẫu SQL.
Đã sửa đổi bảng phone_action_log: Thêm cột assignment_id (INTEGER, NULLABLE) và khóa ngoại tham chiếu đến task_assignments (ON DELETE SET NULL).
Tình trạng Schema: Đã hoàn tất thiết kế và cung cấp các lệnh SQL CREATE TABLE, ALTER TABLE cần thiết. Đã khắc phục các lỗi liên quan đến việc tạo bảng và cột (thiếu bảng, thiếu cột).
B. Server Backend:

Core Flask App (app/__init__.py): Cấu trúc cơ bản, đăng ký các Blueprint (main, admin, phone).
Database Module (database.py): Chứa các hàm tương tác CSDL. Đã bổ sung đầy đủ các hàm CRUD cơ bản cho devices, accounts, device_accounts, task_assignments, macro_definitions, strategies, stages, transitions. Đã có các hàm lấy dữ liệu phức tạp hơn cho Admin UI (ví dụ: get_all_task_assignments với join và phân trang, get_assignment_logs...).
Phone Controller (phone/controller.py):
compile_strategy_package: Chức năng cốt lõi biên dịch cấu hình Strategy (type='control'), Stages, Transitions từ DB thành gói JSON strategy_package cho Client. Đã hỗ trợ các bước simple, conditional, repeat_n (loop), while_condition_met (loop). Đã sửa các lỗi liên quan đến parse JSON và logic biên dịch loop. step_id trong JSON được lấy từ transition_id.
process_phone_report: Xử lý báo cáo từ client, cập nhật task_assignments (tiến độ trong target_data, status cuối cùng, result_data, last_report_at) và ghi log vào phone_action_log.
handle_device_registration: Xử lý đăng ký/cập nhật thông tin thiết bị và liên kết tài khoản từ client (theo workflow mới, hàm này có thể ít dùng cho đăng ký ban đầu hơn, chủ yếu để client check-in).
Phone API Routes (phone/routes.py):
/register_device (POST): Endpoint để client đăng ký/cập nhật. Đã định nghĩa.
/get_strategy (POST): Endpoint chính để client lấy nhiệm vụ. Logic đã được cập nhật: nhận device_id, account_id -> tìm device_account_id -> tìm task_assignments phù hợp -> gọi compile_strategy_package -> trả về JSON package (chứa assignment_id, target_data) hoặc {status: "no_task"}. Đã khắc phục lỗi 404 (cần người dùng kiểm tra lại kết nối mạng/server).
/report_status (POST): Endpoint để client gửi báo cáo. Logic đã được cập nhật: nhận assignment_id, device_id, account_id, status_report -> gọi process_phone_report.
/_internal/accounts_for_device (GET): API nội bộ (đặt trong admin_routes.py) để lấy danh sách account theo device cho form Admin. Đã khắc phục lỗi BuildError.
Admin Routes (admin_routes.py): Chứa các route cho giao diện Admin.
Đã có các route cơ bản cho việc quản lý Accounts, Strategies (Language/Control), Stages (Language/Control), Transitions (Language/Control), Macro Definitions, API Keys, Personas, Templates,...
Đã thêm/hoàn thiện các route cho quy trình mới:
view_devices, add_device, edit_device, delete_device: Quản lý Thiết bị.
view_device_detail, link_account_to_device_route: Xem chi tiết thiết bị và thực hiện liên kết Account vào Device. (Route sửa/hủy liên kết chưa tạo).
view_task_assignments, add_task_assignment: Quản lý và thêm Task Assignment (Giao việc). Có phân trang, lọc, dropdown động.
cancel_task_assignment, delete_task_assignment: Xử lý hủy và xóa Task Assignment. (Route sửa chưa tạo).
view_assignment_logs: Xem log chi tiết theo Assignment ID (có phân trang).
AI Service (ai_service.py): Chứa logic gọi Gemini AI, xử lý intent (cho Language). Tương đối ổn định.
C. Giao diện Admin (Templates):

Layout chung (admin_base.html): Đã cập nhật menu điều hướng (tab-nav) để thêm link "Giao việc", tạm ẩn link "Thiết bị" (do route view_devices chưa hoàn thiện?).
CSS (static/style.css): Đã thống nhất sử dụng file CSS ở thư mục /static cấp gốc. Đã gộp CSS từ /app/static/ và bổ sung các style mới cho bảng (stylish-table), nút bấm (button, button-small...), form (form-group, form-row, fieldset...), status badges, và phân trang (stylish-pagination) để giao diện đồng bộ và chuẩn hơn.
Templates Quản lý Thiết bị:
admin_devices.html: Hiển thị danh sách thiết bị, có phân trang, nút Thêm/Sửa/Xóa. Đã sửa lỗi UI, lỗi phân trang. Nút "Chi tiết" tạm comment out.
admin_add_device.html: Form thêm thiết bị thủ công, đã cho phép nhập device_name, os_info, macrodroid_version. Trường device_name là bắt buộc.
admin_edit_device.html: Form sửa thiết bị, cho phép sửa device_name, notes, status, os_info, macrodroid_version.
Template Chi tiết Thiết bị:
admin_device_detail.html: Hiển thị thông tin device, bảng danh sách các account đã liên kết, form để liên kết account mới. Các nút Sửa/Hủy liên kết tạm thời comment out/disabled. Đã sửa lỗi break tag.
Templates Quản lý Task Assignment:
admin_task_assignments.html: Hiển thị danh sách assignment, có bộ lọc, phân trang chuẩn, các nút hành động (Log, Hủy, Xóa đã hoạt động, Sửa đang chờ). Đã sửa lỗi isinstance.
admin_add_task_assignment.html: Form thêm assignment, có dropdown chọn Device, dropdown chọn Account (cập nhật động theo Device), dropdown chọn Strategy (Control). Đã sửa các lỗi BuildError.
Template Xem Log:
admin_assignment_logs.html: Hiển thị thông tin assignment và bảng log chi tiết có phân trang. Đã tạo và hoạt động.
Helper Template:
_pagination_helper.html: Chứa macro render_pagination tạo HTML phân trang theo kiểu chuẩn (Đầu/Trước/Sau/Cuối + Form nhảy trang). Đã sửa lỗi RecursionError và cập nhật CSS/HTML.
D. Client MacroDroid:

Trạng thái: Chưa bắt đầu triển khai chi tiết.
Kế hoạch: Sẽ bao gồm Macro Chính (Execution Engine) và các Macro Con. Macro Chính chịu trách nhiệm lấy JSON từ Server, phân tích và điều phối việc gọi Macro Con. Macro Con thực hiện các hành động cụ thể (UI Click, Wait...).
Bước tiếp theo: Thảo luận chi tiết cách tạo Macro Con (ví dụ: SYS_WAIT, APP_OPEN...) và logic của Macro Chính.
IV. Trạng thái Hiện tại và Các Bước Kế tiếp Ngay Bây Giờ:

Hoàn thành cơ bản: Backend API và CSDL cho luồng quản lý Device/Account/Assignment theo hướng Admin cấu hình trước. Giao diện Admin cho các chức năng cốt lõi (Xem list, Thêm, một phần Sửa/Xóa/Log) đã được định hình. Phần biên dịch JSON chiến lược hoạt động tốt với các cấu trúc điều khiển.
Vấn đề cần kiểm tra lại:
Kết nối API /phone/get_strategy từ bên ngoài (lỗi 404 cần được giải quyết triệt để - kiểm tra mạng, firewall, địa chỉ/port server, đăng ký blueprint).
Việc lấy transition_id dùng làm step_id trong compile_strategy_package (cần đảm bảo hàm DB trả về đúng ID).
Ưu tiên Tiếp theo:
Giải quyết dứt điểm lỗi 404 khi gọi API /phone/get_strategy.
Bắt đầu thảo luận chi tiết và phác thảo Client MacroDroid: Tập trung vào Macro Con trước (SYS_WAIT, APP_OPEN...).
(Song song hoặc sau Client) Hoàn thiện nốt các chức năng Admin còn thiếu: Sửa/Hủy liên kết Device-Account, Sửa Task Assignment. Tạo trang quản lý/xem danh sách Devices (view_devices) và bỏ comment link trong admin_base.html.
