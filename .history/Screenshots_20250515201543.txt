Mục tiêu: Hiển thị ảnh chụp màn hình (screenshot) của một Node :Screen trong panel chi tiết khi người dùng click vào Node đó trên bản đồ Cytoscape của trang admin_mapping_viewer.html.

Luồng hoạt động chính để hiển thị ảnh (dựa trên các thảo luận trước và cách làm việc hiệu quả):

Backend - API Lấy Dữ liệu Đồ thị (GET /admin/api/mapping_data trong admin_routes.py):

Nguồn dữ liệu: Hàm này gọi graph_db.get_app_graph_data(app_name).
graph_db.get_app_graph_data(app_name) (trong app/graph_db.py):
Khi query các Node :Screen từ Neo4j, nó phải lấy các thuộc tính:
s.app_name
s.screenshot_path (đây là CHỈ TÊN FILE ảnh, ví dụ: image123.png)
s.width (chiều rộng gốc của màn hình khi chụp ảnh)
s.height (chiều cao gốc của màn hình khi chụp ảnh)
Các thuộc tính khác của Node (screen_id, activity_name, status, element_count).
Trong API api_get_app_graph_data (sau khi có dữ liệu thô từ graph_db):
Với mỗi Node :Screen nhận được:
Nó sẽ tạo ra một URL đầy đủ để truy cập file ảnh. URL này sẽ được dùng bởi JavaScript ở frontend.
Cách tạo URL này phải nhất quán với cách server Flask thực sự phục vụ file ảnh đó. Dựa trên thảo luận cuối cùng của chúng ta, URL đúng là /app_screenshots/<filename.png> (không có /admin/ và không có app_name trong path của URL, chỉ có trong path vật lý nếu cần).
Ví dụ tạo URL trong Python (API api_get_app_graph_data):
Python

# ... bên trong vòng lặp xử lý node từ graph_db ...
node_dict = dict(record_from_neo4j) # record_from_neo4j chứa app_name, screenshot_path (chỉ tên file)

if filename:
    try:
        # Giả sử route phục vụ ảnh có endpoint là 'serve_uploaded_screenshots'

        # KHÔNG dùng 'admin.serve_app_specific_screenshot' nếu URL không có '/admin/'

else:
    node_dict['screenshot_full_url'] = None

API này sẽ trả về JSON cho Cytoscape, trong đó mỗi node sẽ có một thuộc tính screenshot_full_url (nếu có ảnh), original_width, và original_height.
Frontend - JavaScript trong admin_mapping_viewer.html:

Khi Cytoscape được khởi tạo: Nó nhận dữ liệu nodes từ API trên.
Khi người dùng click vào một Node (Screen) trên bản đồ:
JavaScript lấy dữ liệu của Node đó từ Cytoscape, bao gồm:
nodeData.screenshot_full_url
nodeData.original_width
nodeData.original_height
nodeData.id (chính là screen_id)
Hiển thị ảnh:
Lấy thẻ <img> trong panel chi tiết (ví dụ: #mapSelectedScreenshotImage).
Gán imgElement.src = nodeData.screenshot_full_url;
Xử lý onload và onerror của ảnh.
Vẽ Overlays (sau khi ảnh đã tải và có kích thước):
Gọi API GET /admin/api/screen_elements_for_mapping/<screen_id> (endpoint api_get_screen_elements_for_mapping) để lấy danh sách elements của Node này từ Neo4j.
Gọi hàm JavaScript drawMapScreenOverlays(imgElement, elementsDataFromApi, nodeData.original_width, nodeData.original_height, screenshotContainerDiv) để vẽ các overlay.
Backend - Route Phục Vụ Ảnh:

File: app/__init__.py (hoặc app/routes.py nếu bạn dùng blueprint gốc).
Định nghĩa:
Python

# Trong app/__init__.py hoặc app/routes.py (đăng ký với app hoặc blueprint gốc)
from flask import send_from_directory, current_app as app_context
import os

# @app.route('/app_screenshots/<path:filename>', endpoint='serve_uploaded_screenshots')
# Hoặc nếu dùng blueprint gốc (ví dụ main_bp):
# @main_bp.route('/app_screenshots/<path:filename>', endpoint='serve_uploaded_screenshots')
def serve_uploaded_screenshots(filename): # Chỉ nhận filename
    logger = app_context.logger 
    # SCREENSHOT_STORAGE_PATH trong config.py PHẢI trỏ đến thư mục vật lý
    # CHỨA TRỰC TIẾP các file ảnh.
    # Ví dụ: 'C:\Users\hocpt\venv\app\static\screenshots'
    storage_path = app_context.config.get('SCREENSHOT_STORAGE_PATH') 

    if not storage_path:
        logger.error("SCREENSHOT_STORAGE_PATH is not configured.")
        return "Storage path error", 500

    logger.debug(f"Serving screenshot (global route): dir='{storage_path}', file='{filename}'")
    try:
        return send_from_directory(storage_path, filename)
    except FileNotFoundError:
        logger.warning(f"Screenshot not found (global route): {os.path.join(storage_path, filename)}")
        return "Image not found", 404
    # ... (xử lý lỗi khác)
SCREENSHOT_STORAGE_PATH trong config.py: Phải được thiết lập chính xác đến thư mục vật lý nơi ảnh được lưu (ví dụ: C:\Users\hocpt\venv\app\static\screenshots).
Tóm tắt các điểm chính để bạn hiểu rõ:

Nơi lưu ảnh vật lý: C:\Users\hocpt\venv\app\static\screenshots\ (theo log bạn cung cấp). Do đó, SCREENSHOT_STORAGE_PATH trong config.py phải trỏ đến đây.
node.screenshot_path (trong Neo4j): Chỉ là TÊN FILE (ví dụ: abc.png).
Route phục vụ ảnh: Một route Flask được định nghĩa ở cấp ứng dụng (ví dụ: trong app/__init__.py) với URL path là /app_screenshots/<filename> và endpoint name (ví dụ: serve_uploaded_screenshots). Route này đọc file từ SCREENSHOT_STORAGE_PATH.
API api_get_app_graph_data (trong admin_routes.py): Khi lấy dữ liệu node, nó sẽ sử dụng url_for('serve_uploaded_screenshots', filename=node.screenshot_path) để tạo ra URL đầy đủ (/app_screenshots/abc.png). URL này được gửi về cho client.
JavaScript (admin_mapping_viewer.html): Nhận screenshot_full_url từ API và dùng nó để hiển thị ảnh.
Tại sao lại có sự nhầm lẫn trước đó?

Ban đầu, có thể tôi đã giả định route phục vụ ảnh thuộc admin_bp (và do đó có prefix /admin/) và có thể cần app_name trong URL path.
Thông tin bạn cung cấp dần dần đã làm rõ rằng URL hoạt động là /app_screenshots/<filename> và thư mục lưu trữ không phân chia theo app_name cho mỗi file.
Với luồng thống nhất này, việc hiển thị ảnh trong admin_mapping_viewer.html (và cả admin_node_management.html sau này nếu dùng chung cơ chế) sẽ hoạt động chính xác.
