==================================================================
README: Quản lý và Sử dụng Screenshots trong App Mapping
==================================================================

Mục lục:
1. Tổng quan về Screenshots
2. Luồng xử lý Screenshots
3. Các thành phần và hàm liên quan đến Screenshots
4. Vấn đề chính đã giải quyết liên quan đến kích thước ảnh
5. Điểm cần lưu ý và kiểm tra tiếp theo

------------------------------
1. TỔNG QUAN VỀ SCREENSHOTS
------------------------------

- Mục đích: Ảnh chụp màn hình (screenshots) được sử dụng để cung cấp ngữ cảnh trực quan cho các màn hình (Screens) được khám phá trong ứng dụng.
- Hiển thị:
    - Trên trang "Chi tiết Elements" (`/admin/screen/<screen_id>/elements`): Ảnh chụp màn hình được hiển thị cùng với các overlay của elements để người dùng phân loại.
    - Trên trang "Bản đồ Ứng dụng" (`/admin/mapping/`): Khi click vào một node (màn hình) trên bản đồ, ảnh chụp màn hình tương ứng (nếu có) sẽ được hiển thị trong panel chi tiết, kèm theo overlay của các elements trên màn hình đó.
- Lưu trữ:
    - Tên file ảnh (hoặc đường dẫn tương đối) được lưu trong thuộc tính `screenshot_path` của node `:Screen` trong Neo4j.
    - File ảnh thực tế được lưu trữ trên server, trong một thư mục được cấu hình (ví dụ: `app_screenshots/APP_NAME/filename.png`).

-------------------------------------
2. LUỒNG XỬ LÝ SCREENSHOTS
-------------------------------------

I. UPLOAD TỪ CLIENT:
   1. Client (MacroDroid/App) chụp ảnh màn hình.
   2. Client gửi file ảnh này lên server thông qua API `/api/upload/screenshot` (trong `app/phone/routes.py`, hàm `upload_screenshot`).
   3. Server lưu file ảnh vào thư mục đã cấu hình (ví dụ: `current_app.config['UPLOAD_FOLDER']` hoặc một cấu trúc thư mục con theo `app_name`), tạo một tên file duy nhất.
   4. Server trả về **tên file duy nhất** này cho client.

II. CLIENT GỬI EXPLORE STEP:
   1. Khi client gửi dữ liệu UI state đến API `/phone/explore_step` (trong `app/phone/routes.py`), nó **bao gồm `screenshot_filename`** (là tên file đã nhận được từ bước upload).
   2. Route này gọi `controller.handle_explore_step` (trong `app/phone/controller.py`).

III. SERVER XỬ LÝ EXPLORE STEP (`controller.handle_explore_step`):
   1. Nhận `screenshot_filename` từ payload.
   2. Sau khi xử lý UI state và xác định `screen_id`, `app_name`, `activity_name`, `elements`, `original_screen_width`, `original_screen_height`, nó gọi:
      `graph_db.merge_screen(..., screenshot_path=screenshot_filename, screen_width=original_screen_width, screen_height=original_screen_height)`
   3. Hàm `graph_db.merge_screen` sẽ lưu `screenshot_filename` vào thuộc tính `screenshot_path` của node `:Screen` trong Neo4j, đồng thời lưu `width` và `height` (kích thước gốc của màn hình).

IV. HIỂN THỊ TRÊN ADMIN UI:

   A. Trang Chi tiết Elements (`admin_screen_elements.html`):
      1. Route `admin_screen_elements` (trong `admin_routes.py`):
         - Lấy `screen_data` từ Neo4j (`graph_db.get_screen_with_elements`), bao gồm `screenshot_path`, `app_name`, `width`, `height`.
         - Tạo `screenshot_url` bằng cách gọi `url_for('serve_app_specific_screenshot', filename=filename_from_neo4j)`.
         - Truyền `screenshot_url`, `original_screen_width` (từ `screen_data.width`), `original_screen_height` (từ `screen_data.height`) vào template.
      2. Template `admin_screen_elements.html`:
         - Thẻ `<img>` sử dụng `screenshot_url` để hiển thị ảnh.
         - JavaScript (`drawOverlays`) sử dụng `original_screen_width`, `original_screen_height` và kích thước client của ảnh để tính scale và vẽ overlay.

   B. Trang Bản đồ Ứng dụng (`admin_mapping_viewer.html`):
      1. JavaScript gọi API `/admin/api/mapping_data`.
      2. Route `api_get_app_graph_data` (trong `admin_routes.py`):
         - Query Neo4j lấy nodes `:Screen`. Query này **phải** lấy cả `n.screenshot_path`, `n.width`, `n.height`.
         - Với mỗi node, tạo `screenshot_url` (dùng `url_for('serve_app_specific_screenshot', ...)`).
         - Trả về JSON nodes, mỗi node chứa `id`, `screenshot_url`, `original_width` (từ `n.width`), `original_height` (từ `n.height`).
      3. JavaScript trong `admin_mapping_viewer.html` (khi click node):
         - Lấy `nodeData.screenshot_url`, `nodeData.original_width`, `nodeData.original_height`.
         - Gán `src` cho thẻ `img#map-screenshot-image`.
         - Sau khi ảnh load và có `clientWidth/Height` > 0:
            - Gọi API `/admin/api/screen_elements_for_mapping/<screen_id>` để lấy elements.
            - Gọi `drawMapScreenOverlays` với `mapScreenshotImage`, `elementsData`, `nodeData.original_width`, `nodeData.original_height`.
         - `drawMapScreenOverlays` sử dụng các kích thước này để tính scale và vẽ overlay (logic tương tự như ở `admin_screen_elements.html`).

V. PHỤC VỤ FILE ẢNH (SERVING):
   1. Route `/app_screenshots/<path:filename>` (hoặc tương tự, ví dụ: `serve_app_specific_screenshot` trong `app/__init__.py` hoặc một file routes nào đó):
      - Sử dụng `send_from_directory` để trả về file ảnh từ thư mục lưu trữ trên server.
      - **QUAN TRỌNG:** Đường dẫn thư mục trong `send_from_directory` phải khớp với nơi file ảnh được lưu trữ khi upload và nơi hàm `admin_screen_elements` (hoặc `admin_mapping_viewer` nếu dùng Pillow) cố gắng đọc file để lấy kích thước (nếu áp dụng phương án đọc kích thước từ file).

VI. XÓA SCREENSHOT (ĐỀ XUẤT LOGIC):
   1. Khi một node `:Screen` bị xóa khỏi Neo4j (ví dụ, thông qua một hàm `graph_db.delete_screen_and_related_data`).
   2. Hàm này cần:
      - Trước khi xóa node, đọc thuộc tính `screenshot_path` và `app_name` của node đó.
      - Sau khi xóa node thành công, xây dựng đường dẫn đầy đủ đến file ảnh trên server (dựa trên `SCREENSHOT_STORAGE_PATH`, `app_name`, và `screenshot_path`).
      - Dùng `os.remove()` để xóa file ảnh.

---------------------------------------------------------
3. CÁC THÀNH PHẦN VÀ HÀM LIÊN QUAN ĐẾN SCREENSHOTS
---------------------------------------------------------

- **Client:** Chụp ảnh, upload lên `/api/upload/screenshot`, gửi `screenshot_filename` trong payload của `/phone/explore_step`.
- **app/phone/routes.py:**
    - `upload_screenshot()`: Xử lý upload file, lưu file, trả về tên file.
    - Route `/phone/explore_step`: Nhận `screenshot_filename`.
- **app/phone/controller.py:**
    - `handle_explore_step()`: Nhận `screenshot_filename` và truyền nó vào `graph_db.merge_screen` dưới dạng `screenshot_path`.
- **app/graph_db.py:**
    - `merge_screen()`: Lưu `screenshot_path` (tên file) vào thuộc tính của node `:Screen`.
    - `get_screen_with_elements()`: Lấy `screenshot_path` (cùng với `width`, `height`) của node `:Screen`.
    - (Đề xuất) `delete_screen_and_related_data()`: Lấy `screenshot_path` trước khi xóa node, sau đó xóa file.
- **app/admin_routes.py:**
    - `admin_screen_elements()`:
        - Lấy `screenshot_path`, `app_name` từ `screen_data` (Neo4j).
        - Tạo `screenshot_url` bằng `url_for('serve_app_specific_screenshot', ...)`.
        - Truyền `screenshot_url` và kích thước gốc vào template.
    - `api_get_app_graph_data()`:
        - Lấy `screenshot_path`, `width`, `height` từ mỗi node `:Screen`.
        - Tạo `screenshot_url`.
        - Trả về `screenshot_url`, `original_width`, `original_height` trong dữ liệu node.
- **Route phục vụ ảnh (ví dụ: `/app_screenshots/<path:filename>`):**
    - Dùng `send_from_directory` để gửi file ảnh từ thư mục lưu trữ trên server.
- **templates/admin_screen_elements.html & templates/admin_mapping_viewer.html:**
    - Thẻ `<img>` sử dụng `screenshot_url` để hiển thị.
    - JavaScript sử dụng `original_screen_width`, `original_screen_height` và `clientWidth`/`clientHeight` của ảnh để tính scale và vẽ overlay.
- **config.py:**
    - `UPLOAD_FOLDER` hoặc `SCREENSHOT_STORAGE_PATH`: Đường dẫn thư mục gốc nơi lưu trữ ảnh chụp màn hình trên server.

-------------------------------------------------------------------
4. VẤN ĐỀ CHÍNH ĐÃ GIẢI QUYẾT LIÊN QUAN ĐẾN KÍCH THƯỚC ẢNH
-------------------------------------------------------------------

- **Ban đầu:** Overlay bị lệch vị trí hoặc không vẽ được do JavaScript không có `original_screen_width` và `original_screen_height` chính xác.
- **Nguyên nhân:**
    1. Client không gửi thông tin kích thước màn hình gốc.
    2. Server không lưu trữ hoặc không truy xuất được kích thước này cho các trang admin.
    3. Kích thước ảnh chụp màn hình thực tế trên server (ví dụ: 1080x2220) khác với giả định ban đầu (ví dụ: 1080x1920), làm sai lệch tính toán scale.
    4. JavaScript gặp khó khăn khi lấy `clientWidth`/`clientHeight` của ảnh ngay sau khi `load` do timing của DOM rendering.
- **Giải pháp đã áp dụng/đang hoàn thiện:**
    1. **Client Gửi Kích Thước:** Client cần gửi `screen_width` và `screen_height` (kích thước màn hình gốc) trong `raw_ui_state`.
    2. **Server Lưu Kích Thước:** Hàm `process_raw_ui_state` và `handle_explore_step` xử lý các giá trị này. Hàm `graph_db.merge_screen` lưu chúng vào thuộc tính `width` và `height` của node `:Screen` trong Neo4j.
    3. **Server Đọc Kích Thước:** Các hàm backend (`admin_screen_elements`, `api_get_app_graph_data`) đọc `width` và `height` từ Neo4j và truyền chúng (dưới tên `original_screen_width`, `original_screen_height`) cho frontend.
    4. **JavaScript Sử Dụng Kích Thước:** JavaScript trên cả hai trang admin sử dụng các kích thước gốc này cùng với `clientWidth`/`clientHeight` của ảnh hiển thị để tính `overallScaleX/Y` và vẽ overlay.
    5. **Xử lý `clientWidth/Height` bằng 0:** Cải thiện logic JavaScript để chờ và thử lại việc lấy `clientWidth`/`clientHeight` sau khi ảnh `load` nếu ban đầu chúng bằng 0, sử dụng `setTimeout` với số lần thử giới hạn.

-------------------------------------------------------
5. ĐIỂM CẦN LƯU Ý VÀ KIỂM TRA TIẾP THEO
-------------------------------------------------------

- **Đảm bảo Client gửi `screen_width`, `screen_height`:** Đây là yếu tố then chốt. Nếu client không gửi, server sẽ không có kích thước gốc chính xác để lưu và sử dụng.
- **Kiểm tra hàm `graph_db.get_elements_for_screen`:** Đảm bảo hàm này trả về đúng cấu trúc dữ liệu element mà JavaScript trong `drawMapScreenOverlays` (của `admin_mapping_viewer.html`) mong đợi (đặc biệt là `element_id` và các trường tọa độ/bounds).
- **Đồng bộ đường dẫn và URL:**
    - `SCREENSHOT_STORAGE_PATH` (config.py) phải là đường dẫn thư mục gốc trên server.
    - Cách client gửi `screenshot_filename` (chỉ tên file hay `APP_NAME/filename.png`).
    - Cách `screenshot_path` được lưu trong Neo4j.
    - Cách route phục vụ ảnh (`serve_app_specific_screenshot`) xây dựng đường dẫn file từ `filename` nhận được.
    - Tất cả phải nhất quán để ảnh có thể được lưu, tìm thấy, và phục vụ đúng cách.
- **CSS của ảnh và container:** Kiểm tra CSS của `mapScreenshotImage`, `mapScreenshotContainer`, `mapScreenshotDisplayArea` trong `admin_mapping_viewer.html` để đảm bảo chúng không vô tình làm cho `clientWidth`/`clientHeight` của ảnh bằng 0.
- **Logic `checkSizeAndFetchElements`:** Đảm bảo vòng lặp chờ kích thước client của ảnh hoạt động ổn định và có giới hạn thử lại hợp lý.
- **Xóa file ảnh:** Nếu chưa có, cần triển khai logic xóa file ảnh trên server khi node `:Screen` tương ứng bị xóa.
