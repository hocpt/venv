# README - Tổng hợp Dự án HPT Automation
# Ngày cập nhật: 23/04/2025

## I. MỤC TIÊU TỔNG THỂ

Xây dựng hệ thống tự động hóa bao gồm:
1.  **AI Ngôn ngữ:** Tự động tương tác dựa trên văn bản (bình luận, tin nhắn) sử dụng các chiến lược được định nghĩa (Rules, Templates, Stages, Transitions) hoặc gọi AI (Google Gemini).
2.  **AI Điều khiển (Trọng tâm):** Tự động hóa các thao tác trên giao diện người dùng (UI) của ứng dụng Android (TikTok, Facebook...) thông qua Client chạy trên điện thoại (dự kiến dùng MacroDroid).
3.  **Admin UI:** Giao diện quản trị tập trung (Flask Web App) để cấu hình chiến lược, quản lý tài khoản/thiết bị/clone, giao việc, theo dõi tiến độ và hỗ trợ xây dựng "Bản đồ App".
4.  **Hỗ trợ Đa nhiệm:** Quản lý nhiều thiết bị, nhiều tài khoản và nhiều bản sao (clone) của ứng dụng trên mỗi thiết bị.

## II. KIẾN TRÚC & CÔNG NGHỆ

* **Backend:** Python, Flask (dùng Application Factory), Waitress (WSGI Server).
* **Database:** PostgreSQL.
* **Client:** MacroDroid + Plugin AutoInput (chạy trên Android).
* **Giao tiếp:** REST API (JSON) giữa Server và Client.
* **AI:** Google Gemini (thông qua `ai_service.py`).
* **Frontend (Admin UI):** Jinja2 Templates, Bootstrap 5 (dựa trên cấu trúc SB Admin), JavaScript.
* **Thành phần khác:** APScheduler (cho tác vụ nền), Psycopg2 (PostgreSQL driver), python-dotenv, cryptography (mã hóa API key).

## III. TRẠNG THÁI HIỆN TẠI (Tính đến 23/04/2025)

**A. Backend Server & Database:**

* **Schema CSDL (`automation_schema.sql`):** Đã được sửa đổi nhiều lần và hiện tại tương đối ổn định. Bao gồm các bảng chính:
    * `accounts`, `devices`, `device_accounts` (quản lý liên kết và clone context).
    * `strategies` (phân biệt `language`/`control`), `strategy_stages` (với PK phức hợp `strategy_id, stage_id`, có `identifying_elements`), `stage_transitions` (có `strategy_id`, các cột `action_*`, `loop_*`, `notes`, timestamps).
    * `macro_definitions`.
    * `task_assignments` (liên kết `device_account_id` với `strategy_id`, có `target_data`, `result_data`, `status`, lịch chạy...).
    * `phone_action_log` (lưu log chi tiết từ client, có cột `received_state_json` để lưu trạng thái UI đã xử lý).
    * Các bảng cho Language AI & Config: `templates`, `template_variations`, `rules`, `ai_personas`, `prompt_templates`, `api_keys`, `ai_simulation_configs`, `suggested_rules`.
    * Các bảng hệ thống: `scheduled_jobs`, `scheduler_commands`, `task_state`.
    * **Mới:** Bảng `api_documentation` (để quản lý tài liệu API động).
* **Database Functions (`database.py`):**
    * Đã triển khai hầu hết các hàm CRUD cơ bản cho các bảng trên.
    * Có các hàm phức tạp hơn cho Admin UI (lấy danh sách kèm join, phân trang...).
    * Hàm `get_strategy_action_sequence` đã cập nhật để lấy đúng các cột (`action_macro_code`, `action_params`...) và lọc trực tiếp theo `strategy_id`.
    * Hàm `add_new_transition`, `update_transition` đã cập nhật để xử lý đúng các trường (bao gồm `strategy_id`, `loop_*`).
    * Hàm `add_phone_action_logs` đã cập nhật để nhận và lưu `received_state_json`.
    * **Cần làm:** Viết các hàm CRUD cho bảng `api_documentation`.
* **Controller (`phone/controller.py`):**
    * Hàm `compile_strategy_package` biên dịch chiến lược Control thành JSON package, hỗ trợ các step `simple`, `conditional`, `loop` (repeat_n, while_condition_met). Đã tích hợp logging chi tiết để debug. (**Lưu ý:** Thứ tự step trong `action_sequence` trả về có thể vẫn chưa đúng logic CSDL, cần kiểm tra lại).
    * Hàm `process_raw_ui_state` xử lý dữ liệu UI thô từ client thành JSON cấu trúc.
    * Hàm `process_phone_report` xử lý báo cáo từ client, gọi xử lý UI state và gọi các hàm DB để cập nhật assignment, ghi log.
* **API (`phone/routes.py`, `routes.py`):**
    * Các endpoint cho client (`/phone/get_strategy`, `/phone/report_status`, `/phone/register_device`) đã được định nghĩa và sửa lỗi. `/report_status` đã sẵn sàng nhận `current_ui_state`. `/get_strategy` trả về được JSON package (có thể sai thứ tự).
    * Endpoint `/phone/process_ui_state` (dùng để test xử lý UI) hoạt động.
    * Các endpoint cho Language AI (`/main/...`) cơ bản đã có.
    * Các endpoint cho Admin UI (`/admin/...`) đã được tạo cho hầu hết các chức năng.
* **AI Service (`ai_service.py`):** Tích hợp cơ bản với Gemini, có logic retry và xoay vòng API key.
* **Scheduler (`scheduler_runner.py`):** Chạy nền, có cơ chế load job từ DB, xử lý command queue.

**B. Admin UI (Giao diện Quản trị):**

* **Layout (`admin_base.html`):** Đã ổn định, sử dụng cấu trúc SB Admin với Bootstrap 5. Các lỗi hiển thị CSS cơ bản đã được khắc phục (yêu cầu `static/style.css` phải chứa CSS layout SB Admin chuẩn).
* **Trang Quản lý:**
    * Các trang xem danh sách (có phân trang, lọc), Thêm, Sửa cho Accounts, Devices, Strategies (Control/Language), Macros, Templates (+Variations), Personas, Prompt Templates, API Keys, Scheduled Jobs, AI Suggestions, AI Simulations về cơ bản đã có.
    * Trang Task Assignments: Xem danh sách (có lọc, phân trang), Thêm mới hoạt động (có dropdown động). Trang Sửa đang chờ hoàn thiện.
    * Trang Xem Log Assignment: Hiển thị log chi tiết, có phân trang, **có nút "Xem UI" mở Modal hiển thị các element UI đã được client gửi về và server lưu trữ**.
* **Trang Tài liệu API Động:**
    * Đã chuyển hướng sang làm theo phương án này (thay vì trang tĩnh).
    * Đã định nghĩa schema bảng `api_documentation`.
    * Đã tạo template `admin_api_docs_list.html` (hiển thị danh sách ngắn gọn, có nút "Xem Chi tiết" dùng Modal và JavaScript để tải dữ liệu chi tiết đã nhúng).
    * **Cần làm:** Viết hàm DB CRUD, Routes Admin CRUD và các Template Form (Add/Edit) cho chức năng này.

**C. Client (MacroDroid):**

* **Trạng thái:** **Chưa triển khai.**
* **Kế hoạch:** Cần xây dựng Macro chính (Execution Engine), vòng lặp quản lý việc chạy các tài khoản/clone khác nhau trên cùng thiết bị, logic gọi API (`/get_strategy`, `/report_status`), logic parse JSON package, **logic nhận diện stage** dựa trên `stages_recognition` và dữ liệu AutoInput UI Query, logic **tìm kiếm và thực thi step** trong `action_sequence`, và các **Macro Con** (`APP_OPEN`, `UI_CLICK`, `SYS_WAIT`, `UI_QUERY_ACTION`...) có khả năng xử lý tham số và ngữ cảnh clone.

**D. Hỗ trợ Bản đồ App (App Map Helper):**

* **Hiện tại:** Server đã có thể nhận, xử lý, lưu trữ UI state. Admin UI đã có thể hiển thị UI state chi tiết trong trang xem Log.
* **Cần làm (Client):** Client cần triển khai việc **lấy dữ liệu UI (dùng AutoInput UI Query)**, đóng gói thành JSON đơn giản (mảng ids, texts, coords...) và **gửi về server** (trong payload của `/report_status`).
* **Cần làm (Admin UI - Giai đoạn sau):** Phát triển tính năng cho phép Admin xem các UI state đã lưu và **chọn các element** từ đó để dễ dàng cấu hình `identifying_elements` cho Stages và `params` cho Transitions.
* **Cần làm (AI - Giai đoạn sau):** Tích hợp AI để tự động gợi ý stage hoặc element từ UI state.

## IV. LUỒNG HOẠT ĐỘNG TỔNG THỂ DỰ KIẾN (Phone - PC - AI)

1.  **Admin (PC - Web UI):**
    * Định nghĩa Macros (hành động cơ bản).
    * Định nghĩa Strategies (Control/Language).
    * Định nghĩa Stages (màn hình/trạng thái) cho từng Strategy, cấu hình `identifying_elements` (có thể dựa vào UI state xem từ Log).
    * Định nghĩa Transitions (luồng đi), chọn Macro, cấu hình `params` (có thể dựa vào UI state xem từ Log), cấu hình Loop/Condition nếu cần.
    * Quản lý Devices, Accounts, và tạo liên kết Device-Account (có `clone_context`).
    * **Giao việc (Assign Task):** Tạo Task Assignment, chọn Device-Account, chọn Strategy (Control), đặt Priority, Schedule, và `target_data` (mục tiêu).
    * (Tùy chọn) Quản lý AI Personas, Prompt Templates, API Keys.
    * (Tùy chọn) Xem/Quản lý Tài liệu API.
    * Theo dõi trạng thái Assignments, xem Logs chi tiết (bao gồm cả UI State).
2.  **Client (Điện thoại - MacroDroid):**
    * **(Logic chính)** Chạy vòng lặp quản lý các `account_id` được cấu hình cho `device_id` của nó.
    * Với mỗi `account_id` đến lượt:
        * Gọi API `/phone/get_strategy` (gửi `device_id`, `account_id`).
        * Nếu nhận về `status: "no_task"`, chuyển sang account tiếp theo hoặc chờ.
        * Nếu nhận về gói JSON chiến lược: Lưu `assignment_id` và `target_data`. Bắt đầu thực thi `action_sequence`.
    * **(Engine thực thi)** Vào vòng lặp:
        * **Nhận diện Stage:** Dùng AutoInput lấy UI state -> So khớp với `stages_recognition` -> Xác định `current_actual_stage`.
        * **Xác định Intent:** Dựa vào trạng thái trước đó hoặc sự kiện UI.
        * **Tìm Step:** Tìm trong `action_sequence` step có `trigger` khớp với `current_actual_stage` và `intent`.
        * **Thực thi Step:** Gọi Macro Con tương ứng với `macro_code`, truyền `params` (bao gồm cả `clone_context` nếu cần), xử lý `loop`/`conditional`.
        * **Log:** Ghi lại hành động và kết quả vào danh sách log cục bộ.
        * **Cập nhật:** Cập nhật `current_stage` dự kiến dựa vào `next_stage_id`.
    * **Báo cáo:** Định kỳ hoặc khi có sự kiện (step xong, lỗi, assignment xong):
        * Lấy UI state mới nhất.
        * Đóng gói thành JSON "đơn giản" (`current_ui_state`).
        * Thu thập các log cục bộ.
        * Xác định `status_report` (trạng thái, tiến độ...).
        * Gọi API `/report_status` gửi `assignment_id`, `device_id`, `account_id`, `status_report`, `logs`, `current_ui_state`.
    * **Kết thúc Assignment:** Khi không tìm thấy step tiếp theo từ stage "finished" hoặc gặp lỗi không thể phục hồi hoặc nhận chỉ thị dừng từ server. Gửi báo cáo cuối cùng. Chuyển sang account tiếp theo trong vòng lặp chính.
3.  **Server (PC - Flask):**
    * Cung cấp Admin UI.
    * Nhận và xử lý các API call từ Client như mô tả ở trên (tìm assignment, biên dịch strategy, cập nhật CSDL, lưu log, xử lý UI state...).
    * Cung cấp các API cho Language AI (nếu Control Strategy cần gọi).
    * Chạy các tác vụ nền (APScheduler).
4.  **AI:**
    * **Hiện tại:** Hỗ trợ Language AI (phát hiện intent, sinh câu trả lời).
    * **Tương lai (Hỗ trợ Bản đồ App):** Phân tích `received_state_json` để gợi ý stage, rules, elements cho Admin.
    * **Tương lai xa:** Tự động tạo chiến lược, hỗ trợ phục hồi lỗi cho client.

## V. KẾ HOẠCH / BƯỚC TIẾP THEO

Dựa trên trạng thái hiện tại và các thảo luận, thứ tự ưu tiên các công việc tiếp theo là:

1.  **Hoàn thiện Trang Quản lý Tài liệu API Động (Ưu tiên 1):**
    * **Cần làm ngay:** Viết các hàm DB CRUD và Routes Admin CRUD cho bảng `api_documentation`. Tạo các template form Add/Edit. Thêm dữ liệu mẫu API vào `seed_data.sql`.
2.  **Bắt đầu Xây dựng Client MacroDroid (Ưu tiên 2):**
    * **Client:** Triển khai logic lấy và gửi UI state về Server.
    * **Client:** Xây dựng Engine thực thi cơ bản (parse JSON, nhận diện stage đơn giản, tìm và chạy step `simple`).
    * **Client:** Tạo các Macro Con cơ bản.
    * **Admin UI (Hỗ trợ Client):** Hoàn thiện trang quản lý Device/Account/Assignment còn dang dở (Sửa/Hủy liên kết, Sửa Assignment).
3.  **Sửa lỗi Sắp xếp `action_sequence` (Ưu tiên 3):** Tìm và khắc phục lỗi khiến thứ tự step trong JSON trả về từ `/get_strategy` không đúng.
4.  **Phát triển Tính năng Bản đồ App Tương tác (Ưu tiên 4 - Giai đoạn sau):** Xây dựng giao diện Admin UI cho phép chọn element từ UI state đã lưu.
5.  **Tích hợp AI sâu hơn (Ưu tiên 5 - Giai đoạn sau).**
